# RoadVision — Models

Trained model artifacts live here. The backend reads this directory through
`backend/app/core/config.py`; no code changes are needed to activate a model.

| File | What it is | Required? |
|---|---|---|
| `best.pt` | Trained YOLOv8n road-damage detector (3 classes) | Needed for real detection |
| `priority_rf.joblib` | Trained Random Forest priority classifier (P1–P4) | Optional |

## Dropping in `best.pt`

When the Colab training run finishes, download `best.pt` from
`runs/detect/<run-name>/weights/best.pt` and place it here:

```
RoadVision/models/best.pt
```

Then restart the backend. `GET /api/ml/status` will report
`detector.ready: true`.

Override the location if needed:

```bash
export YOLO_MODEL_PATH=/absolute/path/to/best.pt
```

## Class order (must match the trained checkpoint)

```
0: Crack
1: Pothole
2: Surface Erosion
```

## Before `best.pt` exists

The backend still starts and every non-ML endpoint works. `POST /api/ml/detect`
returns HTTP 503 with a clear message until the checkpoint is present — it does
not crash and it does not invent detections.

## About `priority_rf.joblib`

Until a Random Forest bundle is present here, priorities come from the
documented rule heuristic and every result is tagged
`priority_source: "rule"`. **Rule-derived priorities are provisional** — they
are not dataset ground truth. The 3-class dataset provides damage types only;
P1–P4 labels are generated by the project's own rule (see `ML_Pipeline.md`
§1.1 for the label-provenance statement to quote in the report).
